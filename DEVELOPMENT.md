# K_fit-colab: development notes

Notes for people changing the notebook or its widgets. User documentation is
in [README.md](README.md); the implementation plan and status are in
[PLAN.md](PLAN.md).

## Layout

```
K_fit-colab/
├── K_fit.ipynb          # the notebook: one section per stage
├── k_fit_colab/
│   ├── session.py       # NotebookSession: shared state and logic (no widgets)
│   ├── widgets.py       # one build_* function per stage, AtomSelector
│   └── colors.py        # residue / element colour schemes and legend
└── tests/test_session.py
```

The notebook holds no logic. Each stage cell calls one function in
`widgets.py`; the widgets read and write a `NotebookSession`; all scientific
work is done by the K_fit engine. Keep it that way: logic in `session.py`
can be tested without a browser.

## Development environment

Clone K_fit next to this repository and use editable installs, so code
changes take effect after a kernel restart:

```bash
# venv
python3 -m venv .venv && source .venv/bin/activate
pip install -e "K_fit[test]" -e "K_fit-colab[test]" jupyterlab

# or conda
conda create -n k_fit -c conda-forge python=3.12 numpy numba biopython ipywidgets jupyterlab pytest
conda activate k_fit
pip install -e K_fit -e K_fit-colab
```

## Tests

```bash
(cd K_fit && pytest -q)
(cd K_fit-colab && pytest -q)
```

- The tests use the structure files in `../K_fit/tests/data`, or the folder
  named by the `K_FIT_TEST_DATA` environment variable.
- The widget tests drive the panels with simulated button clicks. Run them
  with both ipywidgets 7.7.x (long the Colab default) and 8.x.
- `test_gfp_by_pdb_id` runs the CLAUDE.md test case; it downloads from the
  RCSB PDB and is skipped when offline.

## Colab vs local behaviour

- **Stage 1** clones or pulls both repositories and pip-installs them only
  inside Colab (detected by importing `google.colab`); locally it does nothing.
  The repository URLs are `K_FIT_REPO` / `K_FIT_COLAB_REPO` in that cell.
- **Working folder** (`session.default_work_dir`): `/content/k_fit` in Colab,
  `./k_fit_work` elsewhere.
- **Stage 6** downloads with `google.colab.files` in Colab, and prints the zip
  path elsewhere.
- `ipywidgets.FileUpload` works in Colab (tested by the owner). The text
  field also accepts a path to a file uploaded through the file browser.
- **Output folder:** `NotebookSession.clear_outputs` empties it on every
  Load (Stage 2) and before every run, so it never holds files of an earlier run.

## Implementation notes

- ipywidgets 8 leaves a list or dropdown with nothing selected after its
  options are replaced. The code selects the first entry explicitly
  (`AtomSelector._set_options`, `set_copy_targets`).
- Residue and atom choices are `Select` lists rather than dropdowns, because
  browsers do not reliably show per-option colours in a closed dropdown.
  Colours are injected as `<style>` rules per option (`colors.list_style_html`).
- Double-click to add and a real clipboard copy were left out: both need
  custom JavaScript widgets (e.g. anywidget). "Copy matomids to" copies
  within the notebook instead.
- Pairs CSV headers like `name_1.pdb` that are not loaded, but whose base
  `name.pdb` is, create a copy (`NotebookSession.apply_pairs_csv`). The whole
  CSV is checked first; on any error nothing is changed.
- `widgets.run_safely` prints `SessionError` and every `K_fit.errors.KFitError`
  as a one-line ERROR; other exceptions (bugs) print a traceback.
- `K_fit.ipynb` was generated by a script once and is now edited directly.
